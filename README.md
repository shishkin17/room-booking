# Бронирование переговорной

Веб-приложение для бронирования одной переговорной: выбор дня, расписание с бронями и свободными слотами, создание, редактирование и удаление броней.

## Запуск

Требования: Node 22+, pnpm 10.

```bash
pnpm install
pnpm dev            # dev-сервер с моком API (MSW)
pnpm test           # Vitest
pnpm typecheck
pnpm lint
pnpm build && pnpm preview
```

Переменные окружения:

| Переменная          | По умолчанию | Описание                                                            |
| ------------------- | ------------ | ------------------------------------------------------------------- |
| `VITE_USE_MOCKS`    | `true`       | `false` отключает MSW, запросы уходят на реальный бэкенд            |
| `VITE_API_BASE_URL` | пусто        | Базовый URL бэкенда (используется при `VITE_USE_MOCKS=false`)       |
| `BASE_PATH`         | `/`          | Путь, с которого отдаётся приложение |

## Деплой

Приложение полностью статическое: API работает в браузере через MSW, данные хранятся в `localStorage`, поэтому подходит любой статический хостинг с HTTPS.

## Что сделано

- Выбор даты, дата хранится в URL (`?date=YYYY-MM-DD`), доступны ссылки на конкретный день.
- Расписание дня: список броней и свободные слоты между ними.
- Создание, редактирование и удаление брони.
- Состояния UI: загрузка, пустой день, ошибка, ошибка при устаревших данных (stale-error), отправка формы.
- Обработка конфликта 409, адаптивная вёрстка, базовая доступность.
- Панель «Симуляция сервера (демо)»

## Архитектура

```
src/
  domain/            чистый TS: типы, время, правила валидации, расписание.
                     Общий для клиента и мок-сервера, без зависимостей от React.
  api/               интерфейс BookingsApi, http-реализация, ApiError,
                     BookingsApiProvider (контекст, через него API внедряется в приложение)
  mocks/             MSW-хендлеры, «БД» в localStorage, devSettings, DevPanel.
                     Изолирован, загружается динамически только при VITE_USE_MOCKS
  features/bookings/ query-хуки (TanStack Query), форма, схема, маппинг ошибок сервера,
                     компоненты (DayTimeline, BookingCard, диалоги)
  app/               App, Providers, тема
  shared/            общие хуки (useNow)
```

UI зависит только от интерфейса `BookingsApi`. Чтобы перейти на реальный API:

- задать `VITE_USE_MOCKS=false` и `VITE_API_BASE_URL=https://...`, либо
- передать другую реализацию: `<Providers api={myApi}>`.

### HTTP-контракт

| Метод и путь                        | Успех            | Ошибки             |
| ----------------------------------- | ---------------- | ------------------ |
| `GET /api/bookings?date=YYYY-MM-DD` | 200, `Booking[]` | 500                |
| `POST /api/bookings`                | 201, `Booking`   | 409, 422, 500      |
| `PATCH /api/bookings/:id`           | 200, `Booking`   | 404, 409, 422, 500 |
| `DELETE /api/bookings/:id`          | 204              | 404, 422, 500      |

Тело ошибки: `{ code, message, details }`.
